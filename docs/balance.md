# Balance and quota

Both GeoRanker MCP products provide `get_balance` with empty arguments (`{}`). It creates no provider job and spends no MCP query admission units. HTTP and balance-read rate limits still apply, including when query allowances are exhausted or disabled.

The hosted HTTP API provides authenticated `GET /seo/balance`, `GET /scraping/balance`, and the combined installation endpoint `GET /v1/balance`. Use the existing installation headers, or a product-scoped OAuth bearer token for that product's endpoint. There is no caller-supplied account or installation selector. Responses use `Cache-Control: no-store` and the existing Host and Origin checks. A token for SEO cannot read the scraping endpoint, or vice versa.

`quota` reports the authenticated installation's current tier, total admitted usage and effective remaining allowance for rolling hour, day and 30-day windows. The windows count MCP admission units, not provider credits or money. The `scope`, `limit` and `used` describe the tightest remaining installation, IP, device, linked account or shared-service limit for that window. Account and shared-service identifiers are never returned. Own-key work excludes the shared-service ceiling. The same installation shares allowance across tools and products; separate installations, including separately enrolled OAuth connections, can differ.

`nextReleaseAt` is the next unit expiry in the limiting rolling window, not a calendar reset. `retryAt` accounts for every blocking scope within that window and is null when there is no timed retry, including a disabled allowance. All windows must permit the request. Larger reports can require multiple admission units. Paid own-key tiers have null MCP limits and remaining amounts because the provider manages their credit constraint; null does not promise unlimited provider credits.

`providerCredits` contains only the linked account's last signed credit snapshot, its `reportedAt` and `checkedAt` timestamps and a freshness status: `last_reported`, `stale`, or `unavailable`. `exactCurrentBalance` is false because concurrent or recent queries may not yet be reflected. Missing balance evidence is null, never an invented zero. The platform's shared provider balance is private. Existing account-status integration supplies updates; this feature does not implement a new upstream provider balance API or infer provider charges from MCP admission units.

Every dispatched query and result-retrieval tool includes a post-call `balance` snapshot. Tool failures include it under `error.details.balance`, after any completed allowance refund. Validation and transport failures can occur before tool dispatch. If the balance read fails, data results and their original errors are preserved and the balance status is `unavailable`. A post-call snapshot can include concurrent activity, so differences between snapshots are not a per-query billing receipt. Hosts are instructed to report the returned balance and its freshness with results, without making a redundant balance call.

OAuth catalogs include `get_balance`. Installation-based clients opt in with `X-GeoRanker-Balance-Tools: balance-v1`. Existing clients retain their exact catalogs. Updated clients validate the added tool and input schema during setup. Deploy the compatible hosted server before distributing these clients. Local direct-provider development mode has no hosted installation balance and returns `BALANCE_UNAVAILABLE` for this tool.
